# 健身 App 市场调研：架构、设计风格、功能与交互

> 调研对象：Keep、Fitbod、Nike Training Club（NTC）、MyFitnessPal、FitOn 等主流健身 App。
> 目的：为你的健身 App 确定前后端架构、页面风格、功能点、交互方式，并评估你的「新用户信息采集」方案。
> 日期：2026-08

## 一、前后端分离架构（重点）

### 1.1 行业主流形态：移动端优先 + 前后端完全分离

几乎所有主流健身 App 都采用「**前后端分离**」，只是「前端」这一侧的形态有差异，常见三种：

| 前端形态 | 说明 | 代表 |
|---|---|---|
| **原生 App** | iOS(Swift) / Android(Kotlin) 原生开发 | Nike Training Club、Fitbod 的 App 本体 |
| **混合开发（Hybrid）** | 原生壳 + H5（WebView），业务页面用 Web 技术写 | **Keep**（Vue H5） |
| **跨端 / 小程序** | UniApp / React Native / Flutter，一套代码多端 | 大量国内仿 Keep 项目、健身小程序 |

后端则统一是「**API 化**」：客户端只通过 REST/HTTPS 接口与后端通信，接口用 JSON，前后端各自独立部署、独立迭代。

### 1.2 典型分层（从客户端到数据）

```
客户端(App/H5/小程序)
   │  HTTPS + JSON（REST 接口）
   ▼
API 网关（鉴权、限流、路由）
   ▼
后端服务（按业务拆分：用户/课程/训练计划/打卡记录/社区/商城/饮食）
   ▼
数据层：MySQL/PostgreSQL（关系数据）+ Redis（缓存/会话）
        + 对象存储 OSS/CDN（视频/GIF/图片）+ 搜索引擎（动作检索）
```

### 1.3 案例：Keep（最值得参考的国产样本）

来源：[Keep APP 技术研究](https://cloud.tencent.com.cn/developer/article/1720494)

- **混合开发**：前端 H5 + 后端 + 移动端（iOS/Android 壳），大部分界面用 Web 技术。
- **前端框架**：**Vue + vue-router + vuex**（Keep 是 Vue 技术栈）。
- **域名拆分（前后端分离的体现）**：
  - `api.gotokeep.com` —— 后端接口
  - `show.gotokeep.com` —— 主站 H5
  - `m.gotokeep.com` —— 活动 H5
  - `static1.keepcdn.com` —— 静态资源 CDN
  - `apm.gotokeep.com` —— 监控
  - `kit.gotokeep.com` —— 智能设备
- **认证**：接口基于 **JWT**（cookie 里的 `authorization` 字段），无状态鉴权。
- **H5 与原生交互**：通过 **URL Scheme 事件协议**（`keep://webview/...`、`keep://discover_course` 等），前端用 `location.href` 触发原生能力（跳转、扫码、开 WebView 等）。

### 1.4 案例：Fitbod（海外，个性化代表）

来源：[Fitbod Tech Stack](https://the-web-radar.com/companies/fitbod.me)、[Fitbod 新手指南](https://help.fitbod.me/hc/en-us/articles/30721771750039-Getting-Started-with-Fitbod-A-New-User-s-Guide)

- **营销/官网站**：Next.js（React）+ styled-components + WordPress + MySQL（PHP），Cloudflare CDN，**PWA**。
- **App 本体**：原生 iOS/Android。
- **核心差异点**：用 **机器学习（ML）** 分析用户训练数据，实时生成个性化力量训练计划（结合用户身体能力、可用器械、目标）。
- 数据埋点/分析：Mixpanel、Appsflyer；A/B 测试：VWO。

### 1.5 对你项目的启示

1. **MVP 阶段**：你现在定位是「移动端优先 Web App」，天然就是前后端分离——前端纯静态（React/Vue + Vite），数据内嵌 + 素材走 CDN，**无需后端即可上线**（这正是我们前几轮定的方案）。
2. **后端演进路线**：当需要「账号、云同步、个性化计划、社区」时，再按 **API 网关 + 模块化后端**（Node/Go/Java 均可）逐步加；接口设计从一开始就按 REST + JSON + JWT 预留。
3. **素材托管**：GIF/图片放对象存储或 CDN（对应 Keep 的 static CDN），动作元数据走接口。
4. **个性化**：Fitbod 的 ML 是长期壁垒，短期可先用「**规则引擎**」（根据 onboarding 信息 + 动作库元数据生成计划），不必一开始上 ML。

## 二、页面设计风格

来源：[Keep UI 设计亮点](https://cloud.tencent.cn/developer/article/2008833)、[运动 App 体验设计](https://www.uweb.net.cn/zhishiku/wangzhankaifajishu/25089.html)

主流健身 App 的视觉风格高度趋同，可归纳为：

| 维度 | 行业惯例 |
|---|---|
| **导航结构** | **底部 Tab 栏**：4–5 个入口（首页 / 训练·课程 / 记录 / 我的），顶部配横向滑动标签筛选 |
| **布局** | **卡片式** + 大图/动图；信息瀑布流（Feed）承载推荐内容 |
| **配色** | 高饱和「活力色」：Keep 绿、Fitbod 蓝紫、NTC 黑+荧光绿；背景以白/浅灰为主，深色模式标配 |
| **视觉元素** | 大圆角卡片、渐变按钮、动图循环演示、进度环/数据图表、连续打卡日历 |
| **字体图标** | 系统字体 + 线性图标；数字（卡路里/时长/组数）用大号粗体强调 |
| **动效** | 打卡激励动效、训练跟练倒计时、页面过渡轻快（≤200ms） |

**一句话总结**：移动端优先、卡片化、活力色、动图/数据可视化强、深色模式。

（这和我们之前需求文档里定的「底部导航 + 卡片 + 橙色活力色 + GIF 循环」完全一致，方向没问题。）

## 三、功能点（按优先级分层）

### 3.1 核心功能（几乎每家都有）

| 功能模块 | 说明 |
|---|---|
| **动作库 / 课程库** | 按部位/器械/难度浏览，图文+GIF+视频演示（你已具备数据基础） |
| **个性化训练计划** | 基于 onboarding 信息生成，是 Keep/Fitbod/NTC 的核心差异点 |
| **训练跟练** | 动图/视频循环 + 组间计时 + 计数 + 语音/文字提示 |
| **打卡与记录** | 训练日志、组数×次数×重量、打卡日历、连续天数 |
| **数据统计** | 训练时长、消耗、身体数据趋势（图表） |

### 3.2 增长/留存功能

| 功能模块 | 说明 |
|---|---|
| **社区 / 社交** | 动态、话题、达人、小组（Keep 的强项，见[运营体系分析](https://www.shichangbu.com/index.php/know_info/64196.html)） |
| **商城 / 电商** | 器材、装备、课程付费 |
| **饮食 / 营养** | 热量记录、食谱（Keep、MyFitnessPal） |
| **勋章 / 等级 / 成就** | 游戏化激励 |
| **硬件接入** | 手环、体脂秤、跑步机（Keep `kit` 域名） |

### 3.3 变现

- **会员订阅**（去广告、进阶课程、个性化计划）——主流
- 课程/内容付费、商城电商、广告、企业服务

### 3.4 对你项目的功能分层建议

- **V1**：动作库 + 搜索筛选 + 动作详情（GIF+中文讲解）—— 已完成设计
- **V2**：onboarding + 个性化计划 + 训练跟练 + 打卡记录（本地）
- **V3**：账号云同步、社区、商城、饮食、硬件

## 四、交互方式

| 交互点 | 行业做法 |
|---|---|
| **新用户引导（onboarding）** | **分步表单**，一屏一个问题，降低流失；进度条提示；可跳过/稍后完善 |
| **首页** | 个性化推荐 Feed + 「今日训练」入口 + 快捷开始 |
| **动作/课程浏览** | 顶部标签筛选 + 卡片网格 + 搜索框（实时联想） |
| **详情 → 训练** | 点卡片进详情 → 「开始训练」进入跟练页（大图动图 + 计时） |
| **打卡反馈** | 完成训练后弹出激励动效 + 连续天数强化 |
| **筛选** | 底部抽屉（Bottom Sheet）多选部位/器械/难度 |
| **登录/注册** | 手机号/微信/Apple 一键登录；**先体验后注册**（降低门槛） |

## 五、新用户信息采集（Onboarding）—— 结合你的想法

### 5.1 行业标准采集字段

来源：[MyFitnessPal onboarding](https://pageflows.com/post/desktop-web/onboarding/my-fitness-pal/)、[FitOn onboarding](https://pageflows.com/post/android/onboarding/fiton/)、[Adaptive Onboarding for Fitness Apps](https://designlinkai.com/solutions/ai-solutions-for-design-by-category-and-industry/ai-for-ux-ui-optimization-solutions-by-industry/ai-for-ux-ui-optimization-solutions-in-the-fitness-and-wellness-industry/adaptive-onboarding-for-fitness-apps-using-ai-tools/)

| 字段 | 是否必填 | 用途 | 代表 App |
|---|---|---|---|
| 性别 | 必填 | 能量计算、内容区分 | 全部 |
| 年龄 / 出生年份 | 必填 | 能量计算、安全强度 | 全部 |
| 身高 | 必填 | BMI、身体指标 | 全部 |
| 体重 | 必填 | 热量、进度追踪 | 全部 |
| **健身目标**（减脂/增肌/塑形/保持） | **必填** | **决定推荐内容/计划的核心** | 全部 |
| **训练经验/年限**（新手/中级/进阶） | 必填 | 计划难度分级 | Fitbod、NTC、Keep |
| **训练频率**（每周几天） | 常用 | 计划编排 | Fitbod、Keep |
| **可用器械/场地**（自重/哑铃/杠铃/健身房/居家） | 常用 | **生成计划的关键** | Fitbod（核心） |
| **偏好部位/训练类型**（胸/背/腿/核心/有氧；跑步/瑜伽/力量） | 常用 | 内容推荐、首页个性化 | 全部 |
| 伤病/限制 | 选填 | 安全提醒 | NTC、Fitbod |

### 5.2 你的方案评估

> 你的想法：采集 **身高、体重、年龄、健身年限、喜欢练什么**。

**结论：方向正确、且比多数 App 更精简，很好。** 你列的 5 项正好覆盖「身体数据 + 经验 + 偏好」三类核心，没有冗余。

**建议补充 2 个字段**（否则个性化推荐会缺关键输入）：

1. **健身目标**（减脂 / 增肌 / 塑形 / 保持健康）—— 决定给你推荐「力量训练」还是「有氧/减脂」计划，是行业最核心的一问。
2. **可用器械 / 训练场地**（自重 / 哑铃 / 杠铃 / 健身房 / 居家）—— 因为你动作库有 28 类器械，必须知道用户有什么器械，才能从 1324 个动作里筛出他能做的（尤其 325 个自重动作是居家首选）。

> 可选加分项：每周可练几天（决定计划频率）、伤病限制（安全）。

### 5.3 推荐的 onboarding 流程（分步、一屏一问）

```
① 欢迎 + 价值主张（1 屏，一句话说明「能看懂动作 + 生成计划」）
② 健身目标（单选：减脂/增肌/塑形/保持健康）
③ 身体数据（性别 · 年龄 · 身高 · 体重，可滑块/输入）
④ 训练经验（健身多久：完全新手/1年内/1–3年/3年以上）
⑤ 可用器械（多选：自重/哑铃/杠铃/弹力带/健身房…）
⑥ 喜欢练什么（多选：胸/背/肩/臂/腿/核心/有氧）
⑦ 完成 → 生成个性化首页 + 首个推荐计划
```

设计原则：**一屏一问、进度条、允许「跳过/稍后补充」、先体验后注册**（行业普遍做法，降低流失）。

## 六、对你项目的落地更新建议

1. **架构**：维持「移动端优先 Web App + 前端静态 + CDN 素材」，按 REST+JWT 预留后端演进（与现有《开发概要》一致）。
2. **页面风格**：沿用「底部 Tab + 卡片 + 活力色 + GIF 循环 + 深色模式」，无需调整。
3. **功能**：在《需求文档》中新增 **M0「新用户引导（onboarding）」** 模块，作为首次启动必经流程。
4. **onboarding 字段**：按 5.3 落地，采集「目标 + 身体数据 + 经验 + 器械 + 偏好」。
5. **个性化**：V2 用**规则引擎**（onboarding 信息 + 动作库元数据 → 生成计划），长期再考虑 ML（对标 Fitbod）。
